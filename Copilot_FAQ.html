Getting started

What exactly is GitHub Copilot?

An AI assistant that works across your editor, terminal and GitHub: inline suggestions, next edit suggestions, chat, agents that edit files and run tools, code review, and the Copilot CLI. It sends your prompt plus gathered context (open files, instructions, tool results) to a model and returns suggestions, edits or tool calls.

Start with the Introduction and the Feature Tour.

Do I need a paid plan to try it?

No. When you sign in from VS Code without a plan you are enrolled in Copilot Free, which has Auto model selection only, limited agent use and 2,000 completions a month. All plans include the Copilot CLI. The cloud agent needs a paid plan.

How do I set up Copilot in VS Code?

Install VS Code, click the Copilot icon in the status bar, choose Use AI Features and sign in with GitHub. You can also run GitHub Copilot: Sign in from the Command Palette. Steps are identical on Windows, macOS and Linux. See Setup.

How do I install the Copilot CLI?

Pick one:

  • npm install -g @github/copilot (Node.js 22 or later)
  • winget install GitHub.Copilot on Windows (PowerShell 6+ required)
  • brew install --cask copilot-cli on macOS
  • curl -fsSL https://gh.io/copilot-install | bash on macOS or Linux

Then run copilot, type /login, and confirm with copilot version. Details in Setup.

Should I start with VS Code or the CLI?

Start where you already work. VS Code is best for visual diffs and inline suggestions; the CLI is best for terminals, SSH and CI. Both share the same account and repo customizations. Compare them in VS Code agents vs CLI.

Plans & billing

What are GitHub AI Credits? Where did premium requests go?

Copilot billing is now usage-based and measured in GitHub AI Credits. "Premium requests" was the earlier model; you may still see the old term in older docs and READMEs. Higher-cost models consume more credits per request.

How do I see or cap my usage from the CLI?

Run /usage in a session. Set a ceiling with /limits set max-ai-credits, or pass --max-ai-credits on the command line, which is useful for -p runs in CI.

Can I use Copilot with GitHub Enterprise Server?

Copilot is not available on GitHub Enterprise Server. GHE.com accounts are supported: choose Continue with GHE.com when signing in to VS Code, or copilot login --host URL in the CLI.

Using Copilot

What is the difference between Ask, Plan and Agent in VS Code?

Ask answers questions and does not edit. Plan (start with /plan) produces a plan for you to approve first. Agent edits files, runs commands and calls tools in a loop. See the Feature Tour.

Is Autopilot an agent?

No. Autopilot is a permission and continuation mode: it auto-approves tool calls and keeps working without stopping for you. In the CLI it is one of three modes (standard, plan, autopilot) that you cycle with Shift+Tab. Use it only where mistakes are cheap to undo.

What is a harness, and why is "Local" deprecated?

The Session Target dropdown in VS Code picks which agent harness runs your session: Copilot (default), Claude, Codex or Local. The Local harness is deprecated and scheduled for removal by February 2027. Prompt files, handoffs and the .vscode/mcp.json format only work there, so migrate them. Details in VS Code agents vs CLI, step 2.

How do I choose a model?

In VS Code, use the model picker in Chat. In the CLI, use /model, the --model flag or the COPILOT_MODEL environment variable. Choose auto to let Copilot pick. The available model list changes often, so check the picker rather than a fixed list.

Can I run several agent tasks in parallel?

Yes. In VS Code, use the Agents window and pick New Worktree for each session. In the CLI, use /new worktree, /fork, background tasks (Ctrl+X then b) or /fleet. Give each session its own worktree so they do not edit the same files. See Security, Sandboxing, Git Worktrees.

How do I hand a task to the cloud agent?

From the CLI, run /delegate with a scoped prompt. In VS Code, choose the cloud session target. The cloud agent works in an ephemeral Linux environment and delivers a pull request. It needs a paid plan.

Customization

Where do repo-wide instructions go?

In .github/copilot-instructions.md. For rules that apply to some paths only, use .github/instructions/NAME.instructions.md with an applyTo glob in the frontmatter. Generate a starter file with /init in the CLI. Note that instructions do not affect inline suggestions. See Knowledge & learning loop.

AGENTS.md or copilot-instructions.md?

Both work in VS Code and the CLI. AGENTS.md is a cross-tool convention and can be nested in subfolders; the CLI also supports @path imports inside it. A common pattern is project facts (build, test, layout) in AGENTS.md and Copilot-specific style rules in copilot-instructions.md.

Should I still write prompt files?

No. .github/prompts/*.prompt.md only runs on the deprecated Local harness in VS Code. Use agent skills instead: .github/skills/NAME/SKILL.md with name and description frontmatter. Skills appear as /NAME in both VS Code and the CLI. See Skills, Agents, Tools, Hooks, MCP.

When do I use a skill and when a custom agent?

A skill packages a repeatable task (for example "add an endpoint") that any agent can run or that the model loads when relevant. A custom agent (.github/agents/NAME.agent.md) is a persona with its own tools, model and instructions, such as a read-only API reviewer. Pick it in the VS Code agent picker, or with /agent or --agent in the CLI.

My MCP server works in VS Code but not in the CLI. Why?

Usually the file format. The CLI reads .mcp.json or .github/mcp.json with a top-level mcpServers key, plus ~/.copilot/mcp-config.json. It ignores .vscode/mcp.json, which uses servers. Also check that the folder is trusted. Migrate with jq '{mcpServers: .servers}' .vscode/mcp.json > .mcp.json. Walkthrough in VS Code agents vs CLI, step 5.

Do hooks work the same in VS Code and the CLI?

Yes. The VS Code Copilot harness, the CLI and the cloud agent share one format: JSON files in .github/hooks/ with events such as preToolUse. A preToolUse hook can return allow, deny or ask. The cloud agent only reads .github/hooks/*.json and runs bash. See the hooks reference.

Security & privacy

Will an agent run commands without asking me?

Not by default. VS Code starts at the Manual permission level. The CLI auto-allows read-only operations but prompts for writes, destructive shell commands and URLs. Autopilot, Allow all, --allow-all and /yolo remove those prompts. See Security.

Is --allow-all (or /yolo) safe?

Only in a disposable environment. With all prompts removed, a shell command can do anything your user account can: push, delete files or reach the network. Prefer targeted rules such as --allow-tool='shell(git:*)' --deny-tool='shell(git push)'. Deny rules always win over allow rules.

Does turning on the VS Code agent sandbox block network access?

No. With chat.agent.sandbox.enabled on, general network access is still allowed by default; local network access is not. Restrict domains with the sandbox network settings. The sandbox runs on macOS 15+ and Linux/WSL2; Windows 11 support is experimental.

Is content exclusion a security boundary?

No. Admins can configure content exclusion to keep files out of Copilot context, but it is not applied to symlinks or remote file systems, may miss indirect access, and is not guaranteed for third-party MCP servers. Keep real secrets out of the repository.

How do I keep secrets out of prompts and logs?

Never paste secrets into chat. In the CLI, --secret-env-vars VAR redacts named environment variables. Treat MCP servers, web pages and files as possible prompt-injection sources and keep approvals on. For data handling and retention, see the GitHub Copilot Trust Center.

CLI

How do I run the CLI in a script or CI job?

Use copilot -p "PROMPT"; it exits when done. Add -s for response-only output or --output-format=json for JSON Lines. Authenticate with COPILOT_GITHUB_TOKEN set to a fine-grained PAT that has the Copilot Requests permission. Classic ghp_ tokens are not supported. Example in VS Code agents vs CLI, step 7.

Why are my repo hooks and MCP servers ignored with -p?

In programmatic mode they load only when you opt in with GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=true or GITHUB_COPILOT_PROMPT_MODE_WORKSPACE_MCP=true. The folder must also be trusted; --trust-folder trusts it for that single run.

Where does the CLI keep its settings?

In ~/.copilot/ (change it with COPILOT_HOME). User settings live in settings.json; config.json is internal state such as auth and trusted folders. Repo-level settings go in .github/copilot/settings.json. Open settings with /settings or set a key with copilot config KEY VALUE.

How do I undo what the agent just did?

Use /undo (alias /rewind). /session checkpoints lists restore points. Committing before large runs keeps Git as a second safety net.

Troubleshooting

npm install -g @github/copilot fails. What should I check?

Confirm Node.js 22 or later with node --version. If your ~/.npmrc sets ignore-scripts=true, install with npm_config_ignore_scripts=false npm install -g @github/copilot. On Windows, use PowerShell 6 or later, or install with WinGet instead.

The Homebrew command in the README does not match the docs.

The sources disagree. The official docs use brew install --cask copilot-cli; the README shows brew install copilot-cli. Follow the docs, and try the other form only if the cask is not found.

Copilot is ignoring my instructions.

Check what is actually loaded: /env or copilot instruction list in the CLI, and Chat: Open Customizations in VS Code. Confirm the file path and the applyTo glob. CLI subagents only get repo instructions when the agent sets include-custom-instructions: true. Instructions never affect inline suggestions.

Sign-in works, but my company account is not used in VS Code.

For GHE.com, choose Continue with GHE.com, or set github.copilot.advanced to {"authProvider":"github-enterprise"}. To use a different account per workspace, open Accounts → Manage Extension Account Preferences → GitHub Copilot Chat.

The agent gave a confident but wrong answer.

Models can be wrong. Review every change, run the tests, and correct the source: add the missing fact to AGENTS.md or an instructions file so the next session gets it right. Send feedback from the CLI with /feedback. See Knowledge & learning loop and the review checklist in the Onboarding Kit.
