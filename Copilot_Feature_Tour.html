Step 1
✍️ Editor

Suggestions as you type

Two features work without opening chat. Inline suggestions complete what you are typing. Next edit suggestions predict the follow-up edit your change implies, even somewhere else in the file.

Inline suggestion

Priya types a function signature and a docstring. Copilot proposes the body as dimmed "ghost text". She reads it, then accepts it with Tab or keeps typing to ignore it.

app/routers/shipments.pysuggestion shown
@router.get("/shipments/{shipment_id}", response_model=ShipmentOut) def get_shipment(shipment_id: int, db: Session = Depends(get_db)): """Return one shipment or 404.""" shipment = db.get(Shipment, shipment_id) if shipment is None: raise HTTPException(status_code=404, detail="Shipment not found") return shipment

Next edit suggestion

She renames the parameter shipment_id to id_ on one line. Copilot highlights the other lines that still use the old name and offers the matching edit, so she can step through them instead of hunting.

You edit line 2→Copilot suggests the edit on line 4→Accept or skip→Next related edit
ℹ️

Custom instructions do not affect inline suggestions. Good names, docstrings and nearby code are what steer them.

💬 Chat

One chat, three built-in agents

The Chat view sits beside your code. Pick the built-in agent that matches what you want: an answer, a change, or a plan.

AgentWhat it doesChanges files?Use it when
AskAnswers questions about code and conceptsNo (read-only)Leo wants to understand how invoices/views.py works
AgentPlans, edits files, runs tools and commands, iteratesYesPriya wants a new endpoint with tests
PlanProduces a step-by-step plan before any code changes; also via /planNo (plans only)Marco wants to agree an approach for the Ledgerly refactor first
💡

Autopilot is not a separate agent. It is a permission and continuation setting that lets an agent keep going and auto-approve tools. See step 3 before you turn it on.

Session target (harness)

A dropdown picks which harness runs the session. Copilot is the default and the one this hub uses. Claude and Codex are also offered (they may need settings or a specific plan, and your enterprise can disable them). Local is deprecated and scheduled for removal by February 2027. Sessions keep running in the background even if you switch windows.

⚠️

Older tutorials show an "Edit" mode and prompt files. Current docs describe Ask, Agent and Plan; prompt files work only in the deprecated Local harness. Prefer skills for reusable prompts.

🛠️ Agent

Let the agent do the mechanics, keep the approvals

In Agent mode Copilot reads files, edits code and asks to run commands. You approve tool calls according to your permission level.

🤖 VS Code · Copilot Chat Agent · shiptrack
Priya
Implement GET /shipments/{id}/events returning events newest first. Follow our instructions file. Add tests and run them.
Copilot
Plan:
  1. Add TrackingEventOut to app/schemas.py
  2. Add the route in app/routers/shipments.py, 404 if the shipment is missing
  3. Add tests in tests/test_events.py
  4. Run ruff check . and pytest -q
Tool
edit app/schemas.py (+9) · app/routers/shipments.py (+18) · tests/test_events.py (+41)
Tool
Run in terminal: ruff check . && pytest -q [Allow] [Allow in this session] [Skip]
Tool
All checks passed! · 11 passed in 0.62s
Copilot
Done. Three files changed. Review the ordering in the query: I used order_by(TrackingEvent.occurred_at.desc()).

Permission levels

LevelBehaviour
Manual (default)You confirm tool calls that need approval.
AssistedA model-based safety check decides routine approvals and escalates risky ones.
Allow allNo prompts. Use only in isolated sessions.

Set the default with chat.permissions.default; review saved approvals with Chat: Manage Tool Approval in the Command Palette.

Run agents in parallel

The Agents window coordinates several sessions. For each one choose Branch (works in the current folder) or New Worktree (a separate checkout). Worktree sessions always run with Allow all, and git-ignored files such as .env or installed dependencies are not copied into a new worktree.

⚠️

Worktrees isolate files only. The agent still has your machine and network access. Pair them with sandboxing; see Security.

⌨️ CLI

The same agent in your terminal

The Copilot CLI is an agent that runs in any terminal, local or remote. Use it interactively, or script it with a single prompt.

bash — shiptrack
marco@nw:~/shiptrack$ copilot ● Copilot CLI · mode: standard · Shift+Tab to change > Explain how @app/routers/shipments.py validates input Requests are parsed into Pydantic v2 models (ShipmentCreate). FastAPI returns 422 on validation errors before the handler runs. Weight is constrained with gt=0. > !git status --short M app/routers/shipments.py # Shift+Tab → plan mode plan> Add pagination to GET /shipments/{id}/events Plan: 1) add limit/offset query params 2) update query 3) tests for page 1 and 2 Copilot wants to edit app/routers/shipments.py [once] [session] [always for this repo] [deny]
  • Modes: standard, plan and autopilot. Cycle with Shift+Tab, or start with --mode, --plan or --autopilot experimental.
  • Start with a prompt and stay: copilot -i "…".
  • Pick up later: /resume, or launch with --continue / --resume.
bash — shiptrack (CI job)
# one prompt, print only the answer, then exit $ copilot -p "List endpoints without tests" -s POST /shipments/{id}/events # machine-readable output (JSONL) for scripts $ copilot -p "Summarise ruff findings" --output-format=json {"type":"…", …} # allow git reads, block pushes, for this run only $ copilot -p "Draft release notes from recent commits" \ --allow-tool='shell(git:*)' --deny-tool='shell(git push)' $ git diff main | copilot -p "Review this diff for missing tests"

Deny rules always win over allow rules, even with --allow-all. Repo hooks, workspace MCP and extensions are not loaded in -p mode unless you opt in with the matching GITHUB_COPILOT_PROMPT_MODE_* variables.

Output is illustrative. Install and sign-in are covered in Setup.

📌 Instructions

Write your conventions down once

Instruction files are added to every chat and agent request in the repo. They are the single biggest lever on output quality. Both VS Code and the CLI read them.

Where instructions live
shiptrack/
├── AGENTS.md                              # cross-tool; nested files supported
└── .github/
    ├── copilot-instructions.md            # repo-wide
    └── instructions/
        └── tests.instructions.md          # scoped with applyTo
~/.copilot/copilot-instructions.md       # personal, all repos
.github/copilot-instructions.mdsaved
# ShipTrack conventions ## Stack - Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2 (2.0-style select()), Alembic - PostgreSQL in all environments; no SQLite shortcuts ## Code - One router per resource in app/routers/ - Missing records: raise HTTPException(status_code=404) - Never build SQL with f-strings ## Checks before you finish - ruff check . - pytest -q
.github/instructions/tests.instructions.mdsaved
--- name: tests description: How we write API tests applyTo: "tests/**" --- - Use httpx with the FastAPI app, not a running server - One happy path and at least two error cases per endpoint
💡

No file yet? In the CLI run /init (or copilot init) to generate a first draft, then edit it with your team. copilot instruction list shows which files are loaded. Deeper coverage in Knowledge and Customize.

🧠 Models

Choose a model, or let Auto choose

Copilot offers models from several providers. Bigger models can reason better on hard tasks but consume more AI Credits.

Open the model picker in the Chat input and choose a model, or Auto to let Copilot pick. A custom agent can pin its own model in its frontmatter (model:).

bash — shiptrack
# in a session: pick from the current list > /model # save the choice for this repo only > /model --repo # at launch $ copilot --model auto $ COPILOT_MODEL=<model-id> copilot -p "…"

/model can save to --session, --global, --repo or --local. --effort sets reasoning effort where the model supports it.

  • ✓
    Start with Auto and switch only when a task clearly needs more reasoning.
  • ✓
    Free plan users get Auto only.
  • !
    The model list changes often and your org may restrict it. Check the picker, not a blog post.
  • !
    BYOK (bring your own key) adds chat models, but does not replace the Copilot service for inline suggestions.
🔍 Review

A first review pass, not the last one

Copilot can review a diff or a pull request and leave comments. Marco uses it to catch the obvious issues so human review can focus on design.

On github.com

Request Copilot as a reviewer on a pull request. It comments like any other reviewer; you decide what to apply.

In the CLI

/review runs the code-review agent, which does not modify code. /security-review focuses on security. /pr views, creates or fixes a PR.

In VS Code

Review a selection from the editor. Steer it with github.copilot.chat.reviewSelection.instructions.

⌨️ Copilot CLI standard · shiptrack
Marco
/review
Copilot
3 findings on the current changes:
  1. app/routers/shipments.py: limit has no upper bound, so one request can load every event.
  2. tests/test_events.py: no test for an unknown shipment id.
  3. Minor: unused import datetime.
Marco
Cap limit at 100 and add the missing test.
⚠️

Check current docs for PR-side configuration, such as automatic reviews and how instruction files influence review comments. Commit message and PR description instruction settings exist in VS Code but are experimental.

☁️ Cloud agent

Hand a task off and get a pull request back

The cloud agent works on GitHub's infrastructure, not your machine. You give it a task; it works in its own environment and opens a pull request for you to review.

Start the task→Ephemeral Linux environment→Agent edits, builds, tests→Pull request→You review & merge

Three ways to start

FromHow
github.comAssign or start a task for Copilot on the repo
VS CodeChoose the cloud session target for a new session
Copilot CLI/delegate with an optional prompt; Ctrl+E picks local or cloud before the conversation starts
copilot — shiptrack
> /delegate Add OpenAPI examples to every ShipTrack endpoint Task handed to the cloud agent. It will open a pull request on northwind/shiptrack when done.
  • ✓
    Paid plan required.
  • ✓
    Firewalled by default: outbound access is limited to GitHub and Copilot hosts unless allowed.
  • ✓
    Non-interactive: tools are pre-granted, so it cannot stop to ask you. Hooks in .github/hooks/*.json still apply.
  • !
    Write the task like a ticket: goal, acceptance criteria, files involved. Vague tasks produce vague PRs.
