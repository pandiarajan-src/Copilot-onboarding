Step 1
🤖 Overview

An AI pair programmer that can now also act

GitHub Copilot started as autocomplete for code. Today it is a family of AI features that suggest, explain, edit and, as an agent, carry out multi-step tasks using tools.

Inline suggestions→Next edit suggestions→Chat→Agents (local · background · cloud)→Code review · CLI · MCP tools

✍️ Assists while you type

Inline suggestions complete the line or block you are writing. Next edit suggestions predict the next change you are likely to make elsewhere in the file.

💬 Answers and edits on request

Chat sits beside your code. Ask how something works, or ask for a change and review the diff.

🛠️ Works as an agent

An agent plans, reads files, edits code, runs commands and tests, looks at the results and keeps going until the task is done or it needs you.

What "agentic" means in practice

A plain chat answer is text you copy. An agent calls tools: it can search the repo, write files, run pytest in a terminal or call an MCP server. Each tool call returns a result that the model reads before choosing the next step. You decide which tools it may use and when it must ask first.

ℹ️

Copilot uses models from several providers. You can pick one, let Auto pick for you, or bring your own key (BYOK) for chat models. The exact model list changes often, so this hub does not name specific models.

⚙️ Mechanics

Context in, suggestion out, you decide

Every Copilot feature follows the same loop. Knowing it explains most good and bad results.

1 · Your prompt or code+2 · Gathered context→3 · Chosen model→4 · Suggestion / edits / tool calls→5 · You review

What counts as context

  • 📄
    Open files and your selection: the code you are looking at right now.
  • 📌
    Custom instructions: files such as .github/copilot-instructions.md or AGENTS.md that state your team's conventions. (They shape chat and agents, not inline suggestions.)
  • #️⃣
    References you add: files or other items you attach to the prompt explicitly.
  • 🔧
    Tool results: search hits, test output, terminal output and MCP responses that an agent collects as it works.

The agent loop, step by step

💡

Better context beats a longer prompt. If results drift from your conventions, fix the instructions or the files you attach before you rewrite the prompt.

🖥️ Surfaces

Two places to work: the editor and the terminal

This hub covers VS Code and the GitHub Copilot CLI on Windows, macOS and Linux. They share the same repo customization files, so what you set up once works in both.

  • ✓
    Editor: inline suggestions, next edit suggestions and inline chat.
  • ✓
    Chat view: built-in Ask, Agent and Plan agents next to your code.
  • ✓
    Agents window: run and coordinate several agent sessions, each on a branch or its own worktree.
  • ✓
    Session target: choose the harness that runs a session. Copilot is the default; Claude and Codex are options; the Local harness is deprecated and scheduled for removal by February 2027.

Run copilot for an interactive session, or pass -p to run one prompt and exit (handy for scripts and CI).

bash — shiptrack
marco@nw:~/shiptrack$ copilot version (prints the installed CLI version) marco@nw:~/shiptrack$ copilot -p "Summarise what this repo does in 5 bullets" -s - FastAPI service for parcel tracking (ShipTrack) - Shipments and tracking events stored in PostgreSQL via SQLAlchemy 2 - Alembic migrations under migrations/ - pytest + httpx tests under tests/ - CI in .github/workflows/ci.yml runs ruff and pytest marco@nw:~/shiptrack$ copilot Interactive session started. Shift+Tab cycles standard / plan / autopilot.

Output is illustrative. Marco, the tech lead, lives in the terminal, so you will see the CLI in his parts of the story.

Copilot also runs on github.com (code review, the cloud agent), in the Copilot app and in other IDEs such as JetBrains and Visual Studio. This hub mentions them only where a workflow touches them.

📈 Value

Where professional developers actually gain time

Copilot does not replace engineering judgement. It removes friction from work you already know how to judge. Gains vary by task, codebase and how well you set it up.

TaskTypical fitWhy
Boilerplate, schemas, glue codeStrongPatterns are common and easy to verify by reading.
Writing tests for existing behaviourStrongRunning the tests gives fast, objective feedback.
Understanding unfamiliar codeStrongAsk mode explains code without changing it; you check against the source.
Multi-file changes with a clear specGood with reviewAgents handle the mechanics; you still review design and edge cases.
Refactoring legacy codeGood with tests firstSafe only once characterization tests pin current behaviour.
Security-critical or novel algorithmsAssist onlySubtle errors are costly and hard to spot. Treat output as a draft.

ℹ️

Measure benefit on your own work: compare cycle time and review rework on a few real tickets before and after, rather than relying on headline percentages.

⚖️ Responsibility

You own every line that ships

Copilot can be wrong with confidence. It can misread context, invent an API, or pass tests that check the wrong thing. Treat its output like a pull request from a fast new colleague.

Known limits

  • ✗
    It can be wrong. Plausible code is not proof of correct code. Read it, run it, test it.
  • ✗
    It only knows what is in context. Missing instructions or files lead to generic answers that ignore your conventions.
  • ✗
    Instructions do not steer inline suggestions. They apply to chat and agents.
  • ✗
    Content exclusion is not a security boundary. It reduces what Copilot reads but may not catch indirect access.

Your responsibilities

  • ✓
    Review every diff before you commit, exactly as you would a teammate's.
  • ✓
    Never paste secrets (tokens, passwords, customer data) into prompts or instruction files.
  • ✓
    Keep tool approvals on for writes, shell commands and network access unless the session is isolated.
  • ✓
    Treat external content as untrusted. Web pages, files and MCP responses can carry prompt-injection text.
  • ✓
    Follow your org's policy on which plans, models and MCP servers you may use.
🛑

"Allow all" really means all. In the CLI, --allow-all or /yolo removes approval prompts, so a shell command can do anything your user account can: push, delete, call the network. Use it only in a disposable or sandboxed environment. Details in Security.

For how GitHub handles your data, see the GitHub Copilot Trust Center. Retention details depend on your plan; check the Trust Center rather than relying on second-hand numbers.
