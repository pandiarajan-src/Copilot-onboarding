📦 Install

Install VS Code and sign in to Copilot

Install the latest stable VS Code from code.visualstudio.com. The Copilot sign-in is the same on every OS; only the install differs.

  1. Download the User Installer for Windows and run it. No admin rights needed.
  2. Keep Add to PATH ticked so code works in your terminal.
  3. Open a new PowerShell window and confirm: code --version.
  1. Download the macOS build (Universal or Apple silicon) and move Visual Studio Code.app to /Applications.
  2. In VS Code, run Shell Command: Install 'code' command in PATH from the Command Palette (⇧⌘P).
  3. Open a new Terminal and confirm: code --version.
  1. Download the .deb (Debian/Ubuntu) or .rpm (Fedora/RHEL) package and install it with your package manager, or use the distribution's packaged VS Code.
  2. The package puts code on your PATH.
  3. Confirm: code --version.

Sign in to Copilot (all platforms)

Copilot icon in the status bar→Use AI Features→Sign in with GitHub→Authorize in browser
  • Other ways in: the Accounts menu → Sign in with GitHub to use GitHub Copilot, or the command GitHub Copilot: Sign in.
  • GHE.com account? Choose Continue with GHE.com, or set this in your user settings:
settings.json (User)optional
"github.copilot.advanced": { "authProvider": "github-enterprise" }
ℹ️

Chat and agents come from the GitHub Copilot Chat extension (GitHub.Copilot-Chat). Whether it ships pre-installed in your build varies, so if the Copilot icon is missing, check the Extensions view. Always use the latest stable VS Code; no minimum version is published in the pages we checked.

    Wrong account for this repo? Accounts → Manage Extension Account Preferences → GitHub Copilot Chat lets you pick an account per workspace.

✅ Checklist

What the Copilot CLI needs

Marco lives in the terminal, so he installs the Copilot CLI too. It is a separate program, copilot, with its own login.

  • ✓
    An active Copilot subscription (any plan, including Free).
  • ✓
    Node.js 22 or later, only if you install with npm. Check with node --version. WinGet, Homebrew and the install script do not need Node.
  • ✓
    Windows: PowerShell v6 or later.

Signing in: interactive vs token

MethodWhenNotes
Web flowYour laptopDefault with /login or copilot login. Opens a browser.
Device codeSSH box, dev container, remote VMcopilot login --device-code. Enter the code on another device.
Fine-grained PATCI and automationUser-owned token with the Copilot Requests account permission. Pass with copilot login --with-token or an environment variable.
Classic PAT (ghp_)NeverNot supported.

When several token variables are set, the CLI uses the first it finds, in this order:

COPILOT_GITHUB_TOKEN>GH_TOKEN>GITHUB_TOKEN
⚠️

A stray GH_TOKEN or GITHUB_TOKEN in your shell profile (left over from the GitHub CLI or a script) can silently override your interactive login. If copilot signs in as the wrong identity, check these first.

📦 Install

Install the Copilot CLI

Pick one method per machine. Prefer your OS package manager; use npm if your team standardises on Node.

PowerShell 7 — leo
# Option A: WinGet (no Node needed) PS> winget install GitHub.Copilot Found GitHub Copilot CLI [GitHub.Copilot] Successfully installed # Option B: npm (needs Node.js 22+) PS> node --version v22.11.0 PS> npm install -g @github/copilot added 1 package in 9s PS> copilot version (prints the installed version)

Prerelease builds: winget install GitHub.Copilot.Prerelease or npm install -g @github/copilot@prerelease.

zsh — marco
# Option A: Homebrew (variant shown in the GitHub Docs install page) $ brew install --cask copilot-cli ==> Installing Cask copilot-cli copilot-cli was successfully installed! # Option B: install script $ curl -fsSL https://gh.io/copilot-install | bash # Option C: npm (needs Node.js 22+) $ npm install -g @github/copilot $ copilot version (prints the installed version)
⚠️

Sources disagree on the Homebrew command. The GitHub Docs install page uses brew install --cask copilot-cli (prerelease: copilot-cli@prerelease); the github/copilot-cli README shows brew install copilot-cli. We follow the docs. If the cask is not found, check the current install page.

bash — priya
# Option A: install script (also works with wget) $ curl -fsSL https://gh.io/copilot-install | bash # installs under $HOME/.local by default (/usr/local when run as root) # override with PREFIX=... and pin with VERSION=... # Option B: npm (needs Node.js 22+) $ npm install -g @github/copilot $ copilot version (prints the installed version)

If copilot is not found after the script, make sure the install location under PREFIX is on your PATH and open a new shell.

npm blocked by ignore-scripts?

If your ~/.npmrc sets ignore-scripts=true, the package's install step is skipped. Re-run with the override for this one install:

bash
$ npm_config_ignore_scripts=false npm install -g @github/copilot

Keeping it up to date

  • Update now: copilot update, or /update inside a session (/update stable or /update prerelease).
  • Turn off auto-update: set COPILOT_AUTO_UPDATE=false or start with --no-auto-update. Useful when your team pins a version.
  • Other options: release binaries on GitHub Releases, and the container image ghcr.io/github/copilot-cli for headless SDK use.

Prompts are paraphrased: exact wording changes between versions. What matters is the decision. Trusting a folder lets the CLI load that repo's hooks, .mcp.json and plugin settings. Only trust repos you would also run make in.

On a remote box or in CI

bash — build-vm
# no browser here: use the device code flow $ copilot login --device-code # CI: a fine-grained PAT with "Copilot Requests", from your secret store $ export COPILOT_GITHUB_TOKEN="$SHIPTRACK_COPILOT_PAT" $ copilot -p "List the FastAPI routes in app/" --trust-folder

Tokens from /login are stored in your OS credential store. If none is available, they fall back to a plaintext file under ~/.copilot/, so protect that folder on shared machines.

🗂️ Config

Where the CLI keeps its settings

Everything user-level lives in ~/.copilot (Windows: %USERPROFILE%\.copilot). Set COPILOT_HOME to move it; the old --config-dir flag is deprecated.

~/.copilot (the parts you will touch)
~/.copilot/
├── settings.json             YOUR settings (JSONC: comments allowed)
├── config.json               internal state: auth, plugins, trusted folders (don't hand-edit)
├── copilot-instructions.md   personal instructions for every repo
├── instructions/             personal *.instructions.md files
├── agents/  skills/  hooks/    personal customizations
├── mcp-config.json           personal MCP servers
├── permissions-config.json   "remember for this repo" tool approvals
├── providers.json            bring-your-own-key model providers
├── session-state/            saved sessions (for /resume)
└── logs/                     attach these to bug reports
⚠️

Changed in 2026: user settings moved to settings.json. config.json is now internal state only. Older blog posts that tell you to edit config.json are out of date.

Three scopes

ScopeFileCommitted?Set with
User~/.copilot/settings.jsonNocopilot config KEY VALUE --global
Repo.github/copilot/settings.jsonYescopilot config KEY VALUE --repo
Repo, personal.github/copilot/settings.local.jsonNo (git-ignore it)copilot config KEY VALUE --local

Only some keys can be overridden at repo level. Use /settings (alias /config) inside a session to browse what is available.

Example: ShipTrack worktrees branch from main

bash — shiptrack
$ copilot config worktreeBaseRef defaultBranch --repo
.github/copilot/settings.jsoncommitted
// new worktrees start from the default branch, not your current HEAD { "worktreeBaseRef": "defaultBranch" }

Useful environment variables

  • COPILOT_HOME: move the config folder.
  • COPILOT_MODEL: default model for new sessions.
  • COPILOT_AUTO_UPDATE=false: stop auto-updates.
  • COPILOT_GITHUB_TOKEN: token for headless use (see Step 4).
🏢 Enterprise

Behind a proxy or on a managed laptop

Northwind laptops are managed by IT and sit behind a corporate proxy. Here is what we can confirm, and where to check the rest.

GHE.com hosts

VS Code: Continue with GHE.com. CLI: copilot login --host URL, or set COPILOT_GH_HOST (or GH_HOST).

Organisation policy

Owners can disable MCP servers, use an MCP allowlist (blocked if not listed), and stop users from using /allow-all.

Managed policy files

IT can ship hooks via /etc/github-copilot/policy.d/, C:\ProgramData\GitHub\Copilot\policy.d\ or the Windows registry. They always run.

Sandbox floor

Enterprises can enforce a minimum sandbox for the CLI and VS Code agents. See Security.

⚠️

Proxy settings: check current docs. The official pages we read do not document which proxy variables (for example HTTPS_PROXY) the Copilot CLI honours, or how it handles a corporate TLS-inspection certificate. VS Code has its own network and proxy settings. Before rolling out, ask IT to test one machine and read the latest VS Code Copilot setup and CLI install pages.

Ask your admins for

  • ○
    Your seat assignment and which Copilot features are enabled for the northwind org.
  • ○
    Whether Copilot Memory is enabled. It is off for Business/Enterprise until an owner turns it on.
  • ○
    The approved list of MCP servers, and whether the built-in GitHub MCP server is allowed.
  • ○
    Outbound access to GitHub and Copilot hosts through the proxy (IT will need the current host list from GitHub's docs).
