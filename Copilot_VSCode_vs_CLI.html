Step 1
🧭 Orientation

Two surfaces, one Copilot

VS Code and the Copilot CLI are two front ends to the same Copilot account, the same models and the same repository customizations. Pick by where you are working, not by what Copilot can do.

🖥️ VS Code

Editor-first. Inline suggestions, next edit suggestions, the Chat view, built-in agents and the Agents window for parallel sessions. Best when you want to see and steer diffs visually.

⌨️ Copilot CLI

Terminal-first. An interactive TUI started with copilot, plus a programmatic mode (-p) for scripts and CI. Works over SSH, in containers and next to any editor.

What both surfaces share

  • ✓
    Account and plan. Same GitHub sign-in and the same usage-based GitHub AI Credits.
  • ✓
    Instructions. .github/copilot-instructions.md, AGENTS.md and .github/instructions/*.instructions.md.
  • ✓
    Agents, skills and hooks. .github/agents/, .github/skills/ and .github/hooks/*.json (one hook format for the VS Code Copilot harness, the CLI and the cloud agent).
  • ✓
    Your user folder. ~/.copilot/, including the "Copilot Global" MCP config mcp-config.json.

How a request flows in either surface

Your prompt→Context: files, instructions, tool results→Model→Tool calls (with approvals)→Edits / answer

The agent loop is the same: the model calls tools, reads the results and continues until the task is done or it needs you. What differs is the window around that loop.

ℹ️

Northwind Logistics: Priya builds ShipTrack features in VS Code. Marco, the tech lead, reviews and scripts from the terminal with the CLI. Both work on northwind/shiptrack and rely on the same committed customization files.

🖥️ VS Code

The VS Code agent experience

In VS Code you choose an agent, a harness and a permission level. Sessions keep running in the background even if you switch windows.

Built-in agents

AgentWhat it doesUse it for
AskRead-only questions and answers about your code."How does the events table get populated?"
PlanBuilds a plan before any edits. Start it with /plan.Breaking a feature into steps you approve first.
AgentEdits files, runs terminal commands and calls tools in a loop."Add GET /shipments/{id}/events with tests."

Autopilot is not a separate agent. It is a permission and continuation mode that auto-approves tool calls and keeps going without stopping for you. Use it only where the blast radius is small.

⚠️

Still on the Local harness? Plan your move now: convert prompt files into skills and copy MCP servers into an mcpServers file. Step 5 shows how.

Permission levels

Manual (default)

You confirm tool calls that need approval.

Assisted

A model acts as a safety judge for approvals. Tune it with chat.permissions.assisted.instructions.

Allow all

No prompts. Worktree sessions in the Agents window always use this level.

Set the default with chat.permissions.default. Review or reset saved approvals with Chat: Manage Tool Approval and Chat: Reset Tool Confirmations in the Command Palette.

Checkpoints and undo. VS Code has historically let you roll a chat session back to an earlier point. The exact current UI is not confirmed for this build, so commit before large agent runs and use Git as your safety net.

⌨️ Copilot CLI

The Copilot CLI experience

One binary, three ways to work: an interactive session, a single programmatic prompt, and fine-grained approvals that you can preset on the command line.

Run copilot in a repo. Cycle standard → plan → autopilot with Shift+Tab, or start in a mode with --mode, --plan or --autopilot.

bash — shiptrack
marco@nw:~/shiptrack$ copilot ● GitHub Copilot CLI · mode: standard · folder trusted > /model Pick a model, or auto to let Copilot choose. > Explain how @app/routes/shipments.py validates tracking numbers Reads app/routes/shipments.py and app/schemas.py (read-only, auto-allowed) ✓ Validation happens in the Pydantic model TrackingNumber … > !git status --short # ! runs a shell command directly Shift+Tab → plan mode · Ctrl+X then b → background task · Ctrl+Q → queue a message
  • @FILE mentions a file, #NUMBER pulls in an issue or PR, !CMD runs a shell command.
  • /resume (or --continue) picks up an earlier session. /undo (alias /rewind) steps back.
  • /context shows what is loaded; /compact shrinks a long conversation.

-p runs one prompt and exits. Add -s to print only the response, or --output-format=json for JSON Lines you can parse.

bash — shiptrack
# Summarize a failing test log, never write files or push $ copilot -p "Summarize the failures in pytest.log and point to the likely cause" -s \ --deny-tool=write --deny-tool='shell(git push)' 2 failures, both in tests/test_events.py: the cursor is decoded before the id check, so an unknown shipment returns 400 instead of 404 … # Same prompt, machine-readable $ copilot -p "List every API route in app/ with its HTTP method" --output-format=json | jq -c . {"type":"…"} # one JSON object per line
ℹ️

In -p mode, repo hooks, workspace MCP servers and extensions load only when you opt in: set GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=true, GITHUB_COPILOT_PROMPT_MODE_WORKSPACE_MCP=true or GITHUB_COPILOT_PROMPT_MODE_EXTENSIONS=true. --trust-folder trusts the folder for that one run.

Read-only operations run without asking. Writes, destructive shell commands and URLs prompt you. An approval can apply once, for the session, or be remembered for the repo (saved in ~/.copilot/permissions-config.json).

Approval prompt (illustrative)
Copilot wants to run: alembic upgrade head 1. Allow once 2. Allow for this session 3. Always allow in this repository 4. Deny and tell Copilot what to do instead

Preset rules for a session

bash — shiptrack
$ copilot --allow-tool='shell(git:*)' --deny-tool='shell(git push)' # git commands run without prompts, but git push is always refused # deny always wins over allow, even with --allow-all > /permissions assisted # a model judges approvals for you > /permissions show
⛔

--allow-all and /yolo remove every prompt. The shell can then do anything your user account can: push, delete, reach the network. Use them only in a throwaway container or worktree. Devices with a policy can refuse /allow-all.

Migrate an existing .vscode/mcp.json

bash — shiptrack
$ jq '{mcpServers: .servers}' .vscode/mcp.json > .mcp.json # then delete any "inputs", "envFile" or "dev" fields: mcpServers files do not support them
⚠️

Prompt files are a dead end. They only run on the deprecated Local harness. Move each .github/prompts/x.prompt.md to .github/skills/x/SKILL.md with a name and description in the frontmatter; it then works as /x in both VS Code and the CLI.

ℹ️

CLI subagents do not receive repo instructions unless the agent file sets include-custom-instructions: true. Use copilot instruction list or /env to see what the CLI actually loaded.

🎯 Decide

Which one when?

Real Northwind situations, and the surface that fits each. Then try the chooser.

🖥️ Reviewing a 12-file agent change

Leo's first ShipTrack feature touched routes, schemas and tests. VS Code: step through visual diffs and fix lines in place.

⌨️ Nightly test triage in CI

Marco wants a summary of flaky tests each night. CLI: copilot -p … -s in a job, with write and push denied.

⌨️ Debugging on a staging box over SSH

No editor available. CLI: run copilot in the shell and keep approvals on.

🖥️ Learning Ledgerly's 600-line view

Leo needs go-to-definition and inline answers while reading. VS Code: Ask agent plus the editor.

⚖️ Three independent tasks at once

Either: Agents window with New Worktree, or CLI /new worktree per task. Isolate with worktrees in both.

⚖️ Hand a scoped issue to the cloud agent

Either: VS Code cloud session target, or CLI /delegate. Both end in a pull request.

🖥️ Completions while typing

Only VS Code gives inline suggestions and next edit suggestions.

⌨️ You live in Vim or another editor

CLI works next to any editor; Ctrl+G opens your $EDITOR for long prompts.

CI job — shiptrack

Team rules that keep this smooth

  • ✓
    Put shared customization in the repo; keep personal preferences in ~/.copilot/.
  • ✓
    Use .mcp.json (mcpServers), never only .vscode/mcp.json, so the CLI sees the same servers.
  • ✓
    One agent session per branch or worktree. Two sessions in the same folder can edit the same files.
  • ✓
    Classic ghp_ tokens do not work for the CLI. Use a fine-grained PAT with "Copilot Requests".
